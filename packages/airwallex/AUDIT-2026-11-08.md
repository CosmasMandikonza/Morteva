# Airwallex adapter audit against current official documentation (task D1)

**Date:** 2026-11-08 · **Auditor:** Agent D · **Scope:** every endpoint, schema, auth
requirement, API-version note and state mapping implemented in `packages/airwallex`,
checked against the CURRENT official Airwallex builder guide and API reference
(airwallexdev.com/guide; the guide's linked reference docs) — not remembered facts.

**Verdict: the adapter as implemented matches the current documented behavior on
every audited surface. No endpoint, field-name, status-mapping or idempotency
correction was required. Two hardening additions ship with this audit: a
raw-bytes HMAC-SHA256 webhook signature verifier (previously absent — webhooks
were ingested without cryptographic verification), and an extended money
rejection matrix.**

## Method

Each row was verified by fetching the live official documentation on 2026-11-08
and comparing against the implementation file named. Where the guide and the
older ADR 0005 note differ (API versions drift), the CURRENT guide text wins and
the difference is recorded.

## Money semantics (task D2) — explicit conversions and the rejection matrix

Internal money is integer minor units by currency exponent (domain table);
Airwallex exchanges major-unit JSON numbers. Outbound: minor → exact decimal
string (no float math) → number only at the serialization edge. Inbound:
number → `String()` → `fromMajorString`, which rejects more decimals than the
exponent and any binary-float artifact. `money-boundary.test.ts` (this branch)
extends the round-trip property tests with the required rejection cases:
zero/negative amounts, fractional minor units, `0.30000000000000004`-class
artifacts, > 2^53-1 overflow, unsupported currency codes (no silent exponent
guess), and exponent-exact failures (JPY 1.5, USD 0.001 rejected).

Fee honesty: the authorized total equals the settled total for LOCAL transfers
(free per the guide). SWIFT (flat EUR 12.85 example) is out of the smoke's
scope; if a future rail needs SWIFT, the fee must be fetched/quoted and
validated against the authorized total BEFORE approval — noted here so the
"hidden fees make the authorized total insufficient" case has a documented home.
