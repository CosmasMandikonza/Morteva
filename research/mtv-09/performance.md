# MTV-09/12 measured performance — running browser, not estimates

**Environment (identical for every number below):** Chromium (Playwright `chromium` project) with
SwiftShader **software** WebGL (`--enable-unsafe-swiftshader`), Windows, Node 24, viewport
1440×900 @1x, harness build `VITE_MISSION_VIEWER=1`. SwiftShader is a CPU rasterizer — these are
deliberately honest CI-class numbers; on a real GPU the rasterizer leaves the critical path and
frame rates are materially higher. The machine-readable record is `captures/performance.json`
(regenerated by `e2e/mission-viewer-capture.spec.ts` "measure" test).

## Loading

| Metric                                                                | Measured                                                                         |
| --------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| Harness mount → viewer interactive (`waitForSelector` + model settle) | **≈3.0 s** on software GL (includes two GLB parses + first shadow-mapped frames) |
| Navigation DOMContentLoaded / load                                    | 291 ms / 291 ms (local preview)                                                  |
| Model payloads                                                        | 259,676 B (UAV) + 203,056 B (vessel), no compression needed at this size         |

## Rendering (steady state, event-focus framing)

| Metric                 | Measured (SwiftShader)                                                                                     |
| ---------------------- | ---------------------------------------------------------------------------------------------------------- |
| FPS (3-second sampled) | **12 fps** software · **24–54 fps** observed in the hardware-accelerated in-app browser during development |
| Triangles / frame      | 6,268                                                                                                      |
| Draw calls / frame     | 101 (dominated by the vessel's 94 primitives — well under any budget)                                      |
| Tracked GPU resources  | 222 objects, all disposed on unmount (suite-verified: constant across rebuild cycles)                      |
| JS heap (used)         | ≈14.3 MB                                                                                                   |

## Notes

- The vessel (88-node obj2gltf export, 94 primitives) is the draw-call driver; if a future target
  required fewer calls, a mesh merge is the one obvious optimization — deliberately not done now
  (asset file must stay byte-identical to its recorded SHA-256).
- Shadows (1024² PCFSoft) and the 1024² water plane are the other costs; both are theme-scoped and
  already reduced for dark mode.
- 12 fps on software GL still passes every interaction test in the suite; `prefers-reduced-motion`
  removes the hover bob and transitions entirely for users on weak devices.
